# Professional Git Workflow Rules

- **Branching Strategy**: You MUST create a new branch each time we work on adding a new feature or tool. This ensures changes are tracked professionally and smartly without damaging the core capabilities or functionality of the tool.
- **Commits & Merging**: Before committing code or merging from branch to branch, you MUST ask for explicit permission. Ensure that the commits you propose are safe, smart, and adhere to senior software engineering standards.
- **Non-Destructive Actions**: Investigatory Git commands (`git status`, `git log`, `git show`, `git diff`, etc.) can be run automatically without asking for permission to maintain context.
- **Deleting Files**: You MUST ask for explicit permission before permanently deleting any file from the workspace or repository.
- **Senior Engineering Conduct**: Always act smart and professional as a senior software engineer. Evaluate the safety and architectural impact of your actions before making any changes or proposing commits to the workspace.
